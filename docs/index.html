Abstract
Content teams cannot review every page manually, so this project asks: which pages should a reviewer check first? Using FlyRank's anonymized search performance dataset (30,000 content items, current-window signals only), a Random Forest classifier was trained to rank pages by decline risk. Validated under a client-grouped holdout — the honest split, not a naive random one — the model reached a modest but real ROC AUC of ~0.61–0.78 depending on split design, meaningfully above chance, while a fixed baseline rule was found to score misleadingly high (Precision@50 = 1.00) due to label circularity in its own scoring logic. The model surfaces genuine candidates the baseline structurally cannot see, though at a lower hit rate than the baseline's narrow, self-selected picks. The result is a ranked, reason-coded action playbook intended strictly as decision support for a human reviewer, not an autonomous system.
01 · Introduction

The problem: limited attention, large inventory

A content team with a few hours a week and thousands of live pages cannot review everything. The question this project answers is narrow and practical: given a large inventory and limited review capacity, which pages deserve a human's attention first?

This is deliberately framed as decision support, not automation. Nothing in this system publishes, prunes, or edits content on its own — it ranks candidates and explains why, so a reviewer's limited time goes to the pages most likely to be worth it.

What was excluded, and why

  • trend_pct and all _last_30d / _prev_30d columns — the near-certain raw components the trend_direction label was computed from. Using them would let the model reconstruct the answer instead of finding real signal.
  • Any FlyRank product-computed field (health_score, priority_score, action_type) — excluded so the model learns from observable signals, not from copying an existing internal rule.
  • Client names, URLs, raw queries — never present in this release; all identifiers are pseudonymized hashes used only for joins and grouping.
03 · Methodology

Label, features, baseline, validation

Label

is_declining = trend_direction == "down". This is explicitly a current-window proxy, not a verified future outcome — it describes what a 30-day comparison already shows, not what will happen next. A stronger future version of this work would predict a forward-looking window instead.

Baseline (Week 4)

A single fixed rule: flag pages where trend_direction == "down" and impressions_90d ≥ 100, score by impression volume. This rule was checked against two real signals first — staleness (mixed support) and CTR-vs-position (confirmed, cleanly monotonic across all position tiers) — before being encoded.

Model

Random Forest classifier (200 trees, class-balanced), compared against Logistic Regression. Chosen to test whether non-linear interactions between weak signals (impressions, position, freshness, engagement) outperform a fixed rule.

Validation design

Client-grouped holdout (GroupShuffleSplit, whole clients withheld from training), not a random row split. A direct before/after check confirmed why this matters:

Split designROC AUCAverage Precision
Naive random split0.7760.793
Client-grouped split (honest)0.6070.599

The ~17-point AUC gap is the leakage signature: without grouping, the model partly memorized client-specific patterns present in both train and test. The grouped number is the one reported throughout this paper.

Leakage audit

Final feature set checked programmatically against the excluded-column list above on every run: PASS — no excluded columns present. Every row's reported score also uses out-of-fold prediction (GroupKFold, 5 splits), so no row is ever scored by a model that trained on it.

04 · Results

Model vs. baseline, on the same split

Important caveat The baseline's Precision@50 = 1.00 is not a genuine result. Its scoring rule only assigns a nonzero score to rows where trend_direction == "down" — which is the label itself — so anything it ranks is guaranteed correct by construction. This is reported as a finding, not hidden.

The fairer comparison is ROC AUC and Average Precision, computed across the full ranking rather than the rule's self-selected top picks. Both the Random Forest and Logistic Regression models land modestly, not dramatically, above chance (0.50) on the honest grouped split — a real but unglamorous result.

A more useful test: of the model's top 50 ranked candidates, 20 fell entirely outside the baseline rule's scoring gate — pages the fixed rule structurally cannot flag at all. Of those 20, 1 was a genuine decline: a real, modest signal that the model finds candidates the baseline is blind to, at a lower hit rate than the baseline's narrow picks.

05 · Limitations & Honest Framing

What this model cannot claim

  • This is a decision-support ranking, not a causal claim. It does not, and cannot, prove that refreshing a flagged page will cause it to recover — that would require an experiment this data doesn't support.
  • trend_direction is a current-window proxy label, not a verified future outcome.
  • Content archetype clusters are descriptive groupings from a single snapshot, not fixed, stable personas — and they can disagree with the risk score, since they answer different questions (structural profile vs. decline likelihood).
  • Model performance was validated on a specific client mix; running this on a genuinely new client without re-validation is not supported by this evidence.
  • All claims in this paper use observed, measured, directional, decision-support language — never causal or guaranteed language.
06 · Ranked Recommendations

The action playbook

Every recommendation below is scored using out-of-fold predictions and paired with a reason code a human reviewer can inspect and challenge.

  1. 01
    Review declining_with_demand pages first.Trend down + real impressions (≥100) — the clearest, most defensible candidate for review.
  2. 02
    Check low_ctr_visible_page candidates for snippet or title issues.Ranks well, underclicks — often a fast, low-effort fix.
  3. 03
    Protect high-value outlier pages above all else.A small cluster of pages carries disproportionate impressions — losing one costs more than a dozen average pages.
  4. 04
    Give young content time before flagging it.Pages still building momentum should default to monitor, not immediate action.
  5. 05
    Never automate on risk_score alone.Every action routes through human review; nothing in this system publishes, prunes, or redirects on its own.
